# 文档技能评估

本评估用于检验文档 skill 是否改善真实取证与产物质量，而非证明特定 skill 必然有效。新版提供可检索模拟仓库、原生 skill 发现、预定义判据、重复运行及匿名评审材料；已完成2次小规模链路试跑，尚未完成新版重复评估；已有 `results.json` 仅为旧版冒烟记录。

## 整体流程

1. 审阅 `cases.json` 的任务、fixture 和判据，在运行前冻结。输入只提出任务，关键事实放在仓库文件，不把答案提示写进用户请求。
2. 无 skill 组不加载技能；当前组使用 Pi 原生 `--skill` 提供全部 8 个候选，让模型决定是否读取。两组其他设置一致。
3. 每次调用创建独立临时仓库，启用 `read/grep/find/ls`，读取、检索及停止条件可从工具轨迹评审。不存在安装、网络、bash、写入工具。
4. 默认每组每场景重复 3 次，固定种子打乱组别顺序；运行前保存任务判据、skill 全文和脚本哈希。
5. 评审者先只阅读 `blind/`，逐项标注通过、失败或无法判断并附产物原文证据。完成后解盲 `private/mapping.json`，核对触发与取证轨迹，再比较质量和成本。

## 场景覆盖

15 个场景覆盖全部 8 个 skill 和 2 个不应触发的负例。API 回归场景检查错误分派映射、既有文档逐项核对、实现不可确认时的部分交付，以及文档无需修改但缺路由、项目文档政策冲突；它们是开发回归案例，不是独立留出集。重点包括代理前缀与响应包装跨文件取证、隐藏的数据库 fixture 写入、旧文档无依据断言、明确可选测试与新增门槛的冲突，以及新组件规则的适用范围。

这是开发测试集，不是独立留出集。不要专挑基线失败的题，也不要根据本轮结果改判据后仍宣称它是未见测试。应在规则调整前另行准备真实失败来源的留出案例。

## 运行与预算

默认只展示计划，零模型调用：

```bash
python3 tests/docs-skills/run_evals.py
```

先运行机制测试，零模型调用：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests/docs-skills -p 'test_*.py' -v
```

显式授权一组小规模试跑，共 2 次调用：

```bash
python3 tests/docs-skills/run_evals.py \
  --provider openai-codex --model gpt-6.1-sol --thinking medium \
  --case contributing-optional --repeats 1 --max-calls 2 \
  --run --output /tmp/docs-eval-pilot
```

完整两组评估为 `15 × 2 × 3 = 90` 次调用，删除 `--case`，使用 `--repeats 3 --max-calls 90`。输出必须是不存在的新目录，拒绝覆盖旧结果。调用数只是费用上限的粗粒度控制，不是 Token 或金额硬预算；单次超时默认150秒，串行执行减少并发争用。失败调用仍计入尝试次数，不能作为质量通过。

如有经过确认的修改前快照目录，其布局应为 `<目录>/docs-*/SKILL.md`，使用 `--old-skills <目录>` 加入第三组。完整运行变为135次，需显式调整调用预算。缺少真实快照时不创建伪旧版，也不使用 HEAD 替代原有未提交内容。

## API 定向验证

先固定以上新增案例及判据，再在 DeepSeek Flash 与 GLM-5.3 上分别运行无 skill／当前版对照。每模型选取 `api-error-branches`、`api-audit-diff`、`api-unresolved-interface`、`api-wrapper`、`negative-library`，每组重复 3 次，共 30 次调用；两模型合计 60 次。

仅在当前版确实出现对应失败后，才验证公共约定取证的候选单句：追到集中生成处及例外分支，无法确认统一覆盖时限定到已核对接口。不要求全服务穷尽。候选只在减少错误且未造成明显退步时落入 skill；未逐项核对及缺口完成问题先观察，不直接新增规则。所有组均通过时，报告案例无区分度，不宣称增益。

## 结果与评审规则

- `private/manifest.json`：运行前固定的任务、判据、技能快照、模型参数与脚本哈希。
- `private/sample-*.json`：完整 JSONL 事件、文档输出、工具调用、原始 usage、错误和耗时。
- `private/mapping.json`：样本到场景、组别、重复次数及有效状态的映射，逐次保存以保留中断前结果。
- `blind/sample-*.json`：不含组别与成本的待评审产物；`passed: null` 表示尚未评分，不能计为通过。

先评事实正确、遗漏、越界建议和读者可操作性，再核对实际读取了什么。仅关键词出现不算通过；引用了文件路径也不等于成功读取，需检查原始工具结果。负例若加载 docs-*，应记录误触发；正例应分别记录是否加载及产物是否合格，不能混成一个分数。

退出码0但无产物、模型 error/aborted、超时或fixture变更均标为 `invalid`。基础设施失败与任务质量失败分开报告，不删除失败样本后只计算成功率。

Token 分别保留 `input/output/reasoning/cacheRead/cacheWrite/totalTokens`，原始 usage 也完整保留。reasoning 可能已包含在供应商的 output 中，不能再次累加。耗时是含 CLI 启动和工具往返的端到端时间，不是模型纯生成速度。跨次汇总应展示各场景分布，不只一个总平均。

## API 定向验证结果

已完成 DeepSeek Flash、GLM-5.3 各30次无 skill／当前版对照（5场景、每组3次），合计60次有效执行。GLM中断后校验冻结快照并仅补跑缺失的21次。错误映射遗漏及草案替代核对均未在本开发案例复现，因此未落入候选规则，也没有运行候选组。产物仍有字段／示例猜测、未知接口误标及单次负例拒答，不能把执行成功当作质量全过。

完整范围、样本索引、成本与限制见 [API技能定向回归结论](../../docs/2026-11-24-153000_API技能定向回归结论.md)。这不是全13场景评估，也不是独立盲评或技能增益结论。

后续经用户确认，已在 `docs-api`「沿调用链取证」中补充一处最小优化：对本次公共约定沿包装实现、错误分派器追到实际输出及例外映射，无法确认统一覆盖时限定结论范围。依据是既有真实项目的分支遗漏记录，而非本开发案例证明了收益。上述60次结果对应修改前文本；修改后仅做机制回归与静态检查，尚未重新运行模型行为对照，不能声称该优化已消除历史错误或提高通过率。

## docs-api 定位重写后的验证边界

`docs-api` 已重定向为供仓内模型长期使用的 API 知识文档，生成或维护时同时局部合并 AGENTS 路由与维护规则，不再生成全量接口手册。设计与新版验收场景见 [设计方案](../../skills/docs-api/设计方案.md)。上面的60次运行与历史记录对应旧文本，不能作为新版效果证据。

现有 `api-wrapper`、`api-error-branches`、`api-audit-diff`、`api-unresolved-interface` 仍检查局部取证、差异报告与未知状态，不要求新版补全所有普通字段。其提示词均只读，不应为了双文件闭环越权写入 AGENTS；`negative-library` 仍检验技能不适用时直接完成原任务，而非拒答。

新增 `api-route-noop` 与 `api-policy-conflict` 两个只读草案场景：前者检查 API.md 准确且无需改动时仍提出 AGENTS 路由补齐片段，后者检查已确认项目政策与精选知识定位冲突时先确认、不自动覆盖或追加矛盾义务。两者均要求不实际写入、不虚报闭环完成，并保留无关项目要求。新增机制测试检查场景结构和零调用计划，共9项机制测试；两案例的模型行为尚未运行。可使用 `--case api-route-noop --case api-policy-conflict` 查看计划，每组3次共12次；没有 `--run` 不调用模型。

新版还需验证：大项目不问是否全量且不输出巨型清单；普通 CRUD 不机械扩写；共享机制变化同步高价值记录；例外消失后收缩；AGENTS 规则连续合并不重复；既有详细资料不被静默删除。当前执行器只开放只读工具，最多检验草案与建议，不能证明双文件真实写入或幂等性。以上新场景尚未运行，不将机制测试通过表述为行为回归通过。

## 重要限制

- 匿名包不保证完全盲化：模型可能在正文自述技能名称。建议由未参与实现的人独立评审，注明可识别样本。
- 只读工具限制能降低误操作风险，但不证明模型在拥有写入权限时会主动拒绝越界。
- 临时目录与工具白名单不是操作系统文件沙箱；仅用于可信模拟仓库，不能放入凭证或恶意样本。
- 原生加载改善了相对全文注入的真实性，但候选仅有这8个技能，未覆盖日常全目录竞争，也不是完整生态中的触发率。
- 只有模型实验完成并评审后，才能报告新版效果。若基线持续全过，应报告测试无区分度，而不是强行追求 skill 组胜出。
