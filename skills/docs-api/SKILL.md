# 服务接口契约

维护一份调用方能据此联调的**当前契约**，而不是接口设想、实现流水账或验收报告。

## 决定取证深度

新建时覆盖约定范围内的服务与协议；局部更新从变更接口出发，扩展到共享模型、鉴权和响应包装的受影响接口，避免每次全量扫描。先查仓库能回答的问题；服务归属不清或规范冲突会改变契约时才追问，其他未知项保留为具体缺口，继续完成已确认部分。

## 确定范围与入口

先读项目指令、已有 API 文档和相关接口入口。统一使用仓库根目录 `API.md`（不放在 `docs/` 下，不使用时间戳命名）。已有其他位置的 API 资料时，先确认迁移或汇总范围，保留内容并同步引用，避免重复维护。多个服务或多份文档归属不清时，先确认本次覆盖范围。

只要求核对时保持只读，按接口报告差异、证据和影响。

只修改 API 文档及获准迁移所需的引用，不为匹配文档修改业务代码或 `.gitignore`，也不顺带重组其他文档。标准入口被 Git 忽略时报告并询问；只读核对不迁移。大幅重写或拆分已有文档先确认。

## 沿调用链取证

对照路由注册、处理器、鉴权中间件、序列化模型与业务实现，再核对调用方和相关测试。方法与完整路径、访问边界、凭证载体、字段类型与可空性、公共约定的覆盖范围分别取证，依据充分时直接写明结论：处理器名不证明路由，中间件名不证明凭证形式，样例值不证明字段契约。DTO 类型不能独自证明实际 JSON，前端类型或 mock 不能独自证明后端契约。

跨服务时核实代理前缀、路径重写、认证透传和协议转换；外部实现不可见时，记录本地集成边界与未知项，不把调用方预期写成上游保证。文档与已确认规范冲突时，列出证据并确认，不静默选择一方。

完成这一步时，每个待更新契约都有可定位的实现依据，未确认内容已单列；区分源码已核对、测试已验证与环境已部署。

## 写出调用方需要的契约

按项目实际协议选取内容，不强套 REST 模板：

- **服务与访问边界**：服务归属、基础路径、公开或内部接口、认证方式、权限与资源归属限制。通用响应与错误约定注明适用服务和例外。
- **HTTP**：方法和路径；路径、查询、请求头与请求体参数；类型、必填、默认值、可空性和枚举；实际状态码、响应及错误结构。区分 HTTP 状态码与响应体业务码、字段省略与显式 `null`。
- **SSE / WebSocket / RPC**：连接或调用入口、握手鉴权、消息方向与类型、关联标识、顺序、结束与错误语义；取消、断线恢复和重连仅记录已实现行为。
- **业务边界**：会改变调用结果的状态前置条件、分页、配额、幂等、异步完成方式和副作用。区分请求被接受与任务已完成。
- **调用示例与定位**：给出与字段表一致的最小请求、响应或消息序列，附相关源码入口。示例使用虚构数据与凭证占位符。例如异步接口返回任务标识时，分别说明提交成功响应与查询完成状态的入口，不把提交成功写成业务完成。

公共约定集中维护，限定到已核实的使用范围，各模块写差异；接口较多时提供模块索引，关联章节和实现入口，保留已有稳定锚点。字段表与示例遵循同一证据边界：字段存在但类型未知时明确标注未知；示例只展示已确认部分并注明不完整，不先填入猜测值再用脚注声明待确认。数据库映射、部署配置和 UI 规则只保留影响接口调用的部分，其余链接已有专题文档。

## 增量维护与状态区分

将变更落在接口所属章节，同步字段表、示例、公共约定与模块索引，避免在文末追加相互矛盾的“补充说明”。共享模型、鉴权或包装变化时检查所有引用接口；单个服务的约定不自动推广到其他服务或协议。

区分当前、兼容或受限、停用和规划内容。规划与当前契约分区，注明未实现；废弃、删除或版本替代需有实现、发布说明或用户确认依据，不能仅因找不到一个处理器就判定接口已移除。

保留已有验证基线；仅在对应范围完整复核后更新，并写明核对范围。局部更新不刷新全文验证日期，也不把源码提交号当作部署版本。测试执行记录与验收结论留在已有测试文档，通过链接引用。

## 验证与完成

逐项对照受影响接口的方法、完整路径、鉴权、序列化字段、错误分支与协议事件，检查同类接口及共享契约是否遗漏。核对字段表与示例、模块索引、锚点及源码链接的一致性；来源不明或无法验证的行为明确列出。

默认通过源码与已有测试取证，不为编写文档启动服务、安装依赖或调用真实接口。确需执行验证时先检查命令及间接副作用，遵守项目授权；写库、部署或其他有副作用的调用需单独授权。配置仅记必要键名，跳过真实凭证和符号链接内容。

当约定范围内每个受影响接口都有依据、关联内容已同步、契约状态无混淆时完成。汇报修改文件、核对范围、验证方式及未覆盖项，不将静态核对表述为联调通过。
