# 模型 API 知识文档

将未来模型开发、排错和评审 API 时容易遗漏、反复调查的知识沉淀到 `API.md`，并通过 `AGENTS.md` 建立维护闭环。扫描面广，写入有选择；不是把全部接口翻译成文档。

## 确定交付与边界

先读项目指令、已有 API 资料与文档路由。默认直接扫描并提炼，不询问“全量字段级还是索引”；用户限定模块时遵守范围。生成或维护时交付根目录 `API.md` 与 `AGENTS.md` 的局部读取、更新规则；仅要求核对时两文件均只读，报告差异、证据和影响。

只修改这两份文件及获准调整的相关引用，不修改业务代码、`.gitignore` 或重组其他文档。多服务归属无法判断、正式规范冲突、需破坏性替换或迁移已有资料、文件被忽略或项目约束阻止写入时，确认具体问题再继续；其他缺口不阻断已确认部分。已有完整接口手册不因新定位而静默覆盖或删除，先确认保留方式。

外部全量手册或普通函数参考不属于本技能的产物；不适用本技能不代表用户任务不能完成，应按原请求处理，不偷换为精选知识文档。

## 侦察入口与例外线索

先了解服务启动、路由组织与挂载、协议和共享机制，再按项目搜索特殊行为；不逐接口恢复全部参数与响应，也不将侦察清单照抄进文档。

- 定位基础路径、代理重写及 HTTP、SSE、WebSocket、RPC 等实际入口。
- 查鉴权、权限、租户与资源归属检查，寻找豁免和独立校验路径。
- 查响应包装、错误分派和序列化配置，寻找绕过公共约定的分支。
- 搜索异步状态、回调验签、幂等、重试与隐式副作用等线索，再深挖候选。
- 核实已有 OpenAPI、IDL 或正式规范的来源、适用版本、同步方式与覆盖范围；可信定义直接引用，补充缺失语义，不重复抄字段或另建生成系统。

按项目实际裁剪调查深度。广度侦察不等于全接口审计；未覆盖范围如实说明，局部抽查不能证明全局统一或没有例外。

## 筛选并取证

每项候选判断：**是否影响未来修改、排错或评审的判断？是否容易遗漏或需要跨文件重建？是否有充分依据和明确适用范围？** 少量能显著降低定位成本的入口信息也可保留，不为所有模块机械补行。

优先保留：公共行为及例外；鉴权与资源边界；受理、查询、取消、完成的生命周期；副作用、幂等、重试和兼容约束；特殊字段语义，如 `null` 与省略、大整数精度、验签所需原始请求体。只在解释这些知识时展开具体路径、字段或最小示例。

常规 CRUD 全量路径表、DTO 抄录、逐接口样板、框架常识与实现流水账不入文。重要易变事实仍可记录并绑定来源；普通配置数值引用配置符号而非复制值。关键未知或冲突就近说明依据与待确认问题，不填成确定结论。

沿路由注册、处理器、中间件、序列化、业务实现和相关测试核对候选，结论附文件路径与符号或可信规范入口。定位不代替取证：处理器名不证明路由，中间件名不证明凭证载体，DTO或mock不独自证明实际JSON。公共响应和错误需沿包装、分派器追到实际输出及例外映射；无法确认统一覆盖时限定已核对范围。

跨服务核实前缀、认证透传和协议转换；上游不可见时止于本地集成边界。实现与已确认规范或发布承诺冲突时，并列要求、实际观察和影响，确认后处理，不自动以源码覆盖承诺。区分源码核对、测试验证与部署实测。

## 生成与增量维护 API.md

开篇说明文档职责与本次覆盖边界：**这是精选 API 知识，不是完整接口目录；未收录不代表接口不存在，也不代表已确认它遵循公共约定。**

按实际主题组织公共机制、重要例外、非显然业务语义及必要定位导航，支持按章节读取；不设固定条数、行数或强制索引表，不创建空壳章节。每项知识就近附适用范围和来源，公共约定只维护一份，各处写差异。示例仅展示已确认部分，使用虚构数据与凭证占位符，不能用未知类型的猜测值再加脚注补救。

已有文档增量修改所属章节，保留稳定锚点与仍有价值的记录，不在文末堆矛盾补丁。共享机制变化时检查受影响条目，不每次重扫项目。例外消失后删去过时例外，仍有效的兼容或迁移事实继续保留；未知解决后撤标或转为已核实知识。

区分当前、受限、停用、规划和未知。找不到处理器不能证明接口未实现或已删除。只更新实际复核过的范围与验证状态，不以局部修改刷新全文日期，不将源码提交当部署版本。调查流水和验收记录不塞入现行知识正文。

## 局部合并 AGENTS.md

在生成或维护模式下，只要 API.md 已存在或本次创建成功，就检查并补齐 AGENTS.md 的对应路由与维护规则，不以本次是否改写 API.md 为前提。复用已有路由表与维护章节，合并同义条目；无 AGENTS.md 时最小创建。用户明确禁止修改 AGENTS.md 时仅报告维护缺口；只读核对仍不写任一文件。只维护 API 文档对应的路由和规则，不重排其他约束、不盘点其他专题，也不调用 docs-agents 扩大任务。

按项目实际路径与风格合入以下信息，不要求原样复制模板：

```markdown
## API 知识文档

[API.md](API.md) 记录 API 公共机制、例外、非显然业务语义与源码定位，不是完整接口目录。

- 修改、排查或评审 API、鉴权、响应与错误处理、异步流程前，读取相关章节，并沿源码入口核实当前实现。
- 相关行为变化后，核对受影响记录；出现新高价值知识时，在同一任务中补充。普通 CRUD 变更不机械追加清单；失效例外应删除，已解决未知应更新。
- 完成时说明 API.md 更新内容，或无需更新及原因。实现与已确认规范或发布承诺冲突时，说明差异并确认，不静默以实现覆盖承诺。
```

自动维护是后续模型随任务执行的约定，不安装脚本、Hook、CI或后台服务，不要求重新调用本skill。已有规则等价时不重复添加；已有要求与精选知识定位冲突时，指出冲突并确认处理方式，不自动覆盖项目政策，也不追加相互矛盾的义务。未确认前保留原规则，只给出调整建议并报告未完成项。文档路径变化时同步路由，文件写入受阻时说明缺口，不建立失效链接或声称闭环完成。

## 验证与完成

逐项检查新增或修改的知识是否有决策用途、来源与适用范围；核对实际 JSON、错误分支、生命周期和公共机制例外，避免为追求覆盖膨胀成接口手册。检查相关引用、锚点与符号，确认 AGENTS 路由有效、读取条件与更新时机具体且无重复。对仍未知或未覆盖的部分明确标注，不把生成文档视为全项目审计通过。

默认静态读取源码与已有测试，不为写文档安装依赖、启动服务或调用真实接口。确需执行验证时先检查命令与间接副作用，遵守项目授权；有副作用的调用单独确认。配置只记必要键名，跳过真实凭证与符号链接内容。

完成条件是：高价值知识已准确落位，受影响内容已同步，维护路由已建立或复用，缺口如实列出；只读核对则交付证据化差异报告，不写任一文件。汇报修改文件、扫描与复核范围、维护规则更新或无需更新的原因、验证方式及未覆盖项，不将静态核对表述为联调或长期收益已验证。
