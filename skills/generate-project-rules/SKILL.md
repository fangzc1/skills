# 生成项目规则

为 Claude Code 交付有依据、作用域明确的项目规则，而不是通用框架教程。
不限定语言或项目类型；保留新增功能时真正需要的约束、实现配方和易错点，
不因项目使用了某项技术就为它生成独立文件。

## 确认交付边界

先区分创建、局部更新与只读核对，确认目标仓库及消费环境。
在 pi 中为 Claude Code 生成文件是有效交付；用户要求当前 pi 会话自动使用规则时，
说明本技能的限制并确认方向，不擅自改写为 AGENTS.md 或宣称文件已生效。
目标不明且会改变交付时才追问；明确要求生成 `.claude/rules/` 时无需重复确认。
只读核对不写文件，仅解释项目结构也不构成创建规则的授权。

用 `git rev-parse --show-toplevel` 辅助定位根目录；非 Git 项目根据工作目录与配置入口
确定边界，仍有歧义时再问。读取适用的项目指令、已有 `.claude/rules/`、
`CLAUDE.md`、`.claude/CLAUDE.md`、`AGENTS.md` 与相关专题文档，核对内容而非只看文件名。

默认只修改目标仓库的 `.claude/rules/*.md`；迁移旧规则、改入口或修改源码需另行确认。
读取必要文件时跳过真实凭证与符号链接内容，摘录代码前检查敏感信息。

## 按任务范围取证

首次创建先查看项目入口、依赖与构建配置，排除依赖目录、生成物和构建缓存。
局部更新只追踪受影响的规则、配置、实现和调用方，不重做全库盘点。
Monorepo 按相关子项目分别分析，顶层只归纳已确认的跨项目事实。

从配置与任务定义提取真实命令，说明工作目录、前置条件和子项目范围。
区分“仅核对定义”与“已执行验证”；执行前检查间接脚本和副作用，遵守项目权限约束。
生成规则不授权安装依赖、部署、迁移、写库或启动服务，不为验证文档而直接执行这些操作。

围绕候选规则读取同类实现：通常至少 3 个，不足 3 个则全读；已完整读取相关实现时
不重复采样。跨相关功能域或子项目取样，并主动找例外，不能只选相似的典型文件。
发现差异后继续查证、说明各自适用场景或收窄结论；数量达标不代表全库一致。

重点回答以下问题，有证据才写对应内容，不要求每个项目都具备这些机制：

1. **新增功能的配方**：需要修改哪些文件、按什么顺序，入口和调用链如何连接？
2. **工具强制的约束**：lint、类型检查、构建或 CI 实际拒绝什么，适用范围是什么？
3. **公共封装与生成物**：哪些能力已有入口可复用，哪些文件由代码生成或编译期转换产生？
4. **不同写法的选择**：同一需求是否存在多种实现，它们的适用条件与例外是什么？

目录名仅作检索线索，架构和依赖方向以实现与调用关系为准，不按技术栈套分层。
项目特有参数要核实实际取值，例如分页起始页、错误映射、事务边界和迁移入口，
不使用该生态的常见默认值补空缺。陌生 API 的语义无法确认时保留未知，跳过无依据的规则；
非关键缺口不阻断其他证据充分的内容。

## 区分事实与规则权威

每条结论都要引用支持它的源文件、配置或已有规范，依据同时限制其强度和范围：

- **正式约束**：有已确认规范、强制配置或用户确认，才使用“必须”“禁止”等要求。
- **观察到的惯例**：重复源码支持当前做法，写清范围与例外，不自动命名为团队规范。
- **建议或待确认项**：与正式规则分开；无充分依据的建议放在汇报中，不注入常驻规则。

例如，发现多个枚举只能说明这些位置使用枚举，不能推出“项目禁止所有魔法值”。
已有封装的存在也不自动证明禁止自行实现；要求复用需有相应规范或明确适用条件。
代码与正式规范冲突时报告差异并确认，不用当前实现静默取代正式要求。

## 写入最少必要文件

文件按实际主题命名，使用描述性中文文件名；数量由独立规则及其作用域决定，
不按技术清单凑齐。没有新增的项目特有知识时允许不生成文件，小项目也不强制兜底输出。

目录地图与构建测试说明仅在确有必要且现有资料未覆盖时生成。
已有资料覆盖同一事实时优先引用权威来源，不复制正文；核对引用路径及目标环境中的
读取条件，必要时在规则中写明何时读取。需要修改其他入口才能建立路由时先确认。

更新前读取旧内容，仅修改受影响部分，保留用户改动与仍然有效的约束。
新观察与旧规则冲突时区分过期事实与正式要求，无法判定的冲突单列给用户决定；
不静默覆盖、删除或把新旧两套相反要求同时保留为有效规则。

每个文件一句话说明用途，正文区分正式约束与观察，引用具体依据，说明怎么做及必要理由。
实现配方可摘录最小真实代码，先脱敏，不为每条规则机械附代码块。
写明具体复核条件，例如相关配置、封装接口、目录或生成流程变化时更新。

### 限定加载作用域

局部规则使用 `paths`，glob 相对目标仓库根目录；证据所在文件不一定是规则约束的文件，
应按实际适用对象选择路径。Monorepo 的子项目规则限定到对应子目录。

```yaml
---
paths:
  - "apps/web/**/*.tsx"
---
```

示例路径须替换为项目真实路径。`paths` 是规则作用域的有效字段，拼写或类型错误可能
造成加载异常；约束强度等说明放在正文，不依赖自定义 frontmatter 字段。
无 `paths` 的规则会在会话开始加载，仅用于确需全局适用的少量内容，不能作为 glob 不确定时的降级方案。

## 完成标准

- **证据与权威**：逐条核对依据是否支持结论及其强度，引用路径真实，范围不超出证据；
  已查相关例外，观察和未知没有被写成正式禁令。
- **作用域**：核对 YAML 语法、`paths` 拼写、列表值及 glob。每个 pattern 检查应匹配的真实路径，
  每条局部规则检查不应匹配的路径（如其他子项目），不能只确认至少命中一次。
  无反例可查时说明未覆盖范围；无 `paths` 的文件逐个确认全局加载理由。
- **保留与可达**：已核对受影响旧规则，保留用户改动，消除无意重复；引用入口有效，
  读取及更新条件明确，冲突与未确认项没有混入有效要求。
- **验证状态**：区分文件已生成、静态校验通过与 Claude Code 加载已验证。
  普通 glob 检查不等于目标加载器验证，未实测加载时如实注明；命令核对也不冒充执行成功。

汇报创建、更新或无需生成的文件及作用域、核对结果、未验证项、跳过的相关内容与原因、
待确认冲突。不穷举项目未涉及的所有技术类别，也不因存在未验证项声称全部生效。
