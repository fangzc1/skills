# 认证与连接排错

仅在凭据、权限、证书或连接异常时读取。正常交付使用阶段脚本，不手工重写 API 请求；流程和结果状态见 [SKILL.md](../SKILL.md)。

## 凭据与权限

- Git 认证与 GitLab API 认证独立：fetch/push 成功不证明 API token 可用。
- API 凭据从环境变量 `GITLAB_TOKEN` 读取。只检查是否已设置，不输出值、请求头，不写入日志、描述或命令行参数。
- 401/403 时停止，说明凭据或权限问题，请用户核对项目访问权限；不反复重试。
- `preflight --check-only` 不调用 API，不需要 token；普通交付模式的 API 错误仍会阻断，不声称只是一条警告。

## 证书与地址

- Python API 的企业 CA 可通过 `GITLAB_CA_BUNDLE` 追加信任，系统级 `SSL_CERT_FILE` 也可使用；Git HTTPS 的证书信任需在 Git/系统侧配置，例如 `http.sslCAInfo`。一侧配置不保证另一侧生效。
- 保持 TLS 校验，不关闭、不绕过代理。缺少 CA 时说明需要可信 CA 文件或正确的本机信任配置。
- 子路径部署、fork、主机映射或重定向异常时核对项目地址，不猜 API 基址，不把凭据转发到其他主机。

## 连接中断后的恢复

- Git 网络错误后先区分读取失败和写入结果未知，特别是 push 超时，核对远端 SHA 后再决定下一步。
- 创建 MR 的 POST 结果未知时，脚本会先查询；仍返回 unknown 就报告未知及已知外部动作，不直接重跑写入。排除连接问题后先查询核验现有 MR，再决定是否创建。
