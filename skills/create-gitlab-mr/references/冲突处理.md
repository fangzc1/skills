# Cherry-pick 冲突取舍

仅在 `resolve` 返回 `conflict`、需要判断适配方式时读取；机械流程见 [SKILL.md](../SKILL.md)。

- 比较当前 pick 提交的父版本、该提交与目标工作区，区分双方意图；独立有效改动都保留，业务取舍不明才询问。
- **ours = 目标基线及已迁移内容；theirs = 当前选定提交，不是原源分支全部内容。**不要因一处冲突整文件选边，带入未选改动或丢掉目标改动。
- 二进制只能整体选取时，说明依据；无法确定有效版本再询问。
- schema、权限、计费等冲突按实际行为判断风险，不因文件名就一律加确认；数据库迁移不执行。
- 锁文件不手工拼接；清单和锁文件无法安全一致时说明阻断，不擅自安装/升级依赖重生成。
- 子模块指针比较提交祖先关系，分叉时确认，不自动更新子模块。
- 继续提交保留 hooks。语法或空白检查不能证明接口、权限、计费等行为适配正确。
