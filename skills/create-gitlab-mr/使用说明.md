# 安装与维护

本文件供维护者使用；任务执行流程以 [SKILL.md](SKILL.md) 为准，不在这里重复。维护整体流程、性能取舍、候选去重或命名规则时，参考 [Skill 设计方案](设计方案.md)。

## 安装与依赖

将整个目录复制或链接到 agent 的 skill 目录。需要 Git ≥2.38、Python ≥3.9（仅标准库）及目标仓库的 Git 权限；GitLab API 凭据从 `GITLAB_TOKEN` 读取，企业 CA 可设置 `GITLAB_CA_BUNDLE`，不关闭 TLS 校验。

主入口为 `preflight`、`resolve`、`deliver`。参数使用 `python -I scripts/gitlab_mr.py <子命令> --help` 查看。

## 测试

在此目录运行：

```sh
python3 -B -I evals/test_gitlab_mr.py
```

使用临时 Git 仓库、本地 bare remote 和 mock HTTP，不访问真实 GitLab。`-B` 避免生成 Python 缓存。`evals/evals.json` 是静态演练，不代表已完成模型对照。

回归覆盖工具行为，不能证明实际提速；端到端收益须在相同模型、工具与输入下比较结果正确性、模型往返和墙钟耗时。

## 兼容接口

以下旧入口保留给现有调用方及底层回归，不是主流程执行清单：`snapshot`、`prepare`、`preview`、`project-info`、`branch-name`、`worktree`、`start-merge`、`ensure-mr`。历史整体 merge 测试只验证底层兼容行为，不代表当前主流程仍使用整体 merge。
