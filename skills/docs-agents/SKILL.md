# 项目指引与文档路由

使用 `/writing-for-agents` skill 处理信息层次、上下文指针和内容取舍。本技能负责项目特有的三件事：核实约束、汇总文档、建立助手维护契约。

## 按任务规模取证

创建或全面整理时盘点项目入口与专题覆盖；局部更新只追踪受影响的规则、路由与维护条件，不强制重做全库盘点。先利用仓库中可查的信息；只有作用域、迁移范围或正式规则冲突会改变结果时才追问。非关键缺口单列，不阻断已有证据支持的更新。

## 核实入口

读取项目指令、README、文档入口与验证命令定义，按需对照源码。复用已有指引的位置、语言和作用域，保留安全约束与用户改动；大幅重写先确认。

每条正式约束需已有规范、强制配置或用户确认，观察到的惯例和建议另列。完成这一步时，待写规则的依据、相关文档的真实路径与职责都应明确；未知项列为具体问题。

只要求审计时全程只读，按文件报告证据、影响和建议，不写入新规则。不要因文件名或文档存在就认定内容有效；抽查路由条件能否让助手找到相关事实。

## 为已有文档建立路由

每个相关文档说明四件事：**负责什么、在哪里、何时读取、何时更新**。大型知识库指向主题入口，不穷举子文档；一项事实保留一个来源。

例如，仅在实际存在该文件时写入，并替换为真实路径和条件：

```markdown
| 文档 | 负责内容 | 读取条件 | 更新时机 |
|---|---|---|---|
| [架构概览](ARCHITECTURE.md) | 模块边界与核心数据流 | 调整模块或核心链路前 | 模块职责、依赖或核心数据流变化时 |
```

缺失文档先列为建议。全面整理时，写出已有文档路由后，逐项盘点以下 8 类专题在项目中的适用性与覆盖现状（**已覆盖 / 部分覆盖或缺失 / 不适用及依据**）。只有已存在对应职责的根目录标准专题文档才算“已覆盖”；若仅零散分布在 `README.md`、`CLAUDE.md`、`AGENTS.md` 或子目录片段中，必须列为“部分覆盖（缺失独立专题文档）”。只要存在“部分覆盖或缺失”的适用专题，必须向用户完整列出并询问是否现在生成；用户同意后立即调用对应 skill 生成文档，再回到本文件补齐路由。

8 类专题文档统一使用仓库根目录下的标准文件名（**不放在 `docs/` 下，不使用时间戳命名**）。这是常驻维护入口，不套用一次性文档的默认命名规则：

- 架构（`ARCHITECTURE.md`）：使用 `/docs-architecture` skill。
- API 契约（`API.md`）：使用 `/docs-api` skill。
- 测试指南（`TEST.md`）：使用 `/docs-test` skill。
- 项目安全说明（`SECURITY.md`）：使用 `/docs-security` skill。
- 贡献指南（`CONTRIBUTING.md`）：使用 `/docs-contributing` skill。
- 完成清单（`CHECKS.md`）：使用 `/docs-checks` skill。
- UI 规范（`UI-DESIGN.md`）：使用 `/docs-ui-design` skill。
- 术语表（`GLOSSARY.md`）：使用 `/domain-modeling` skill。

根目录标准入口不存在但已有同职责资料时，标为“部分覆盖”，建议汇总或迁移，复用内容而非重复编写；主题入口可链接专项资料，不复制其正文。迁移先确认范围，保留用户改动并同步相对链接和引用。根目录已有文件但内容不足时也标为“部分覆盖”，文件名本身不证明覆盖完整。

只读审计仅报告盘点与建议，不生成或迁移；用户暂缓、拒绝、证据不足或 skill 不可用时，明确保留未完成项，不声称专题全部补齐。术语表使用 `GLOSSARY.md`；ADR 是独立决策记录，按 `/domain-modeling` 的条件处理，不用术语表替代。

缺少 skill 时说明情况。写入 AGENTS.md 的路由和维护规则只引用项目实际文档，不依赖生成它们的 skill。文档任务不授权修改 `.gitignore`；标准入口被忽略时报告阻碍并询问。

## 合并助手维护契约

在 AGENTS.md 中保留项目特有约束、必要验证入口与前置条件，专题内容通过路由读取。合并以下规则，与已有同义规则保留一份，并按项目实际文档调整：

```markdown
## 文档自动维护

- 修改前按文档路由读取相关资料；修改后按更新条件核对，需要时在同一任务中同步文档。
- 文档新增、移动、删除或职责变化时，同步本文件的路由；项目约束或验证入口变化时，同步对应章节。
- 描述过期时对照源码修正；代码与已确认规范冲突时先说明并确认。术语变更经确认后写入，决策记录保留历史并标明取代关系。
- 文档修改后核对链接、源码路径和命令；完成汇报说明更新文档，或无需更新及原因，未验证项如实列出。
```

自动维护指后续助手随任务执行这些规则，不安装脚本、CI 或 hook，也不新增测试或发布门槛。

## 完成标准

所有写入的约束有依据，相关文档都有有效路由及具体更新条件，维护契约已合并且无重复；全面整理时，8 类专题文档均已按“独立专题文档”标准盘点覆盖状态；局部更新已核对受影响路由。部分覆盖或缺失的适用文档已全部向用户确认是否调用对应 skill 生成，获准生成的文档均使用根目录标准文件名并回填至 AGENTS.md 路由；暂缓或无法生成的专题单列原因。检查命令定义、链接与源码路径；已有验证日期仅在全文复核后刷新。

命令区分已验证与未验证及原因。执行前检查间接脚本与副作用，遵守项目验证规则；CI 步骤不自动成为本地要求，安装、部署、迁移、写库或启动服务需单独授权。跳过真实凭证与符号链接内容。

汇报修改文件、专题覆盖盘点（已覆盖 / 部分覆盖或缺失 / 不适用及依据）、核对结果、未覆盖项与待确认问题。
