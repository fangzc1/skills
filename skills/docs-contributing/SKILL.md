# 贡献指南

为贡献者写一条从准备环境到提交改动的**参与路径**，让首次参与者知道下一步做什么，而不是套用开源项目模板。

## 决定本次维护范围

新建时梳理从环境准备到提交的参与路径；局部更新只核对受影响步骤及其前后置条件。先查仓库可回答的问题；协作政策冲突或目标贡献群体不清会改变流程时才追问。未知的非关键政策不补写，列出缺口并继续整理可证实步骤。

## 先核实实际流程

读取项目指令、README 与已有贡献指南，再核对工具链版本、依赖与命令定义、CI、Issue／PR 模板及已有协作规范。按需查看代表性代码与提交记录；记录中的惯例不自动成为强制规则。

统一使用仓库根目录 `CONTRIBUTING.md`（不放在 `docs/` 下，不使用时间戳命名），保留已有指南的语言、作用域和用户改动。多个入口先明确各自职责；大幅重写或合并先确认。

已有其他位置的贡献指南时，先确认迁移或汇总范围，保留内容并同步引用，避免重复维护。只读核对不迁移；标准入口被 Git 忽略时报告并询问，不修改 `.gitignore`。只修改贡献指南及获准迁移所需的引用；用户只要求审计或核对时保持只读，报告过期内容、缺口与依据。涉及真实凭证或符号链接的内容跳过，不将敏感信息写入文档。

目标文件与拟写流程的来源明确后再落笔。规范与实现冲突时说明差异并确认，不擅自将任一方改成另一方。

## 按贡献者的行动组织

按仓库实际情况取舍以下内容，有证据才写，不为凑齐章节填充通用建议：

- **开始之前**：贡献范围、问题反馈入口，以及已有的大改动事先讨论要求。
- **开发准备**：工具链、依赖准备、工作目录、必要配置键名和外部服务前置条件，链接已有详细安装说明。
- **修改与验证**：改动应遵循的规范、必要验证入口及适用范围，区分本地要求与 CI 专属步骤。
- **提交与评审**：已有分支、提交信息、Issue／PR 内容要求及评审流程；未知的审批人、响应时限或合并策略留作待确认项。

正式要求需由已有规范、强制配置或用户确认支持；观察到的惯例明确标注，建议留在汇报中等待确认。CI 存在某步骤不等于贡献者必须在本地执行，也不由本技能新增覆盖率、签署协议或发布义务。

例如 CI 会自动发布产物，只能据此说明提交后的自动流程；不能推导出贡献者本地必须发布或拥有发布凭证。

贡献指南保留必要入口与隐藏前置条件，详细测试方法链接已有测试指南，交付条件链接已有完成清单，助手专属指令留在 AGENTS.md。缺少专题文档时写清当前必需步骤，不创建失效链接或顺带生成其他文档。

增量更新时，只修正受影响的步骤和引用，保留无关的协作约定；没有变化时说明无需修改，不为产生差异重写全文。

## 验证与完成

沿“准备环境 → 修改 → 验证 → 提交”走读文档，确认每个已记录的步骤都有来源，工作目录、前置条件和下一步清楚，所有文件路径、文档链接与命令定义有效。尚未确定的政策与当前生效要求分开，不用猜测补齐。

核对命令不等于执行命令。获准试运行时，先检查间接脚本和副作用；安装依赖、启动服务、部署、迁移或写库需单独授权，不为验证指南创建 Issue、提交 PR 或执行 git commit。

区分命令已执行验证与仅核对定义，说明未运行或失败的原因。已有全文验证日期仅在全文复核后刷新。

汇报修改文件、流程核对结果、未验证项及待确认问题；只读核对则附问题位置与修正建议。
